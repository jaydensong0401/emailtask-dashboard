01 / DISCOVER

메일을 읽은 뒤에도,
업무를 이해하는 일이 남았습니다.

개인 업무에서 발견한 반복 상황을 출발점으로 삼았습니다. 메일 본문을 읽고, 지난 답장을 찾고, 내 담당인지 확인하는 과정이 업무를 시작할 때마다 이어졌습니다.

CONTEXT

흩어진 맥락

최초 요청과 수정·확정 내용이 여러 답장에 나뉘어 있어 대화 이력을 다시 읽어야 했습니다.

OWNERSHIP

모호한 내 업무

참조된 메일과 직접 요청받은 일이 섞여, 무엇을 내가 처리해야 하는지 구분이 필요했습니다.

FOLLOW-UP

따로 기억하는 상태

이미 처리한 일, 회신을 기다리는 일, 바뀐 기한을 메일과 별개로 기억해야 했습니다.

기획의 출발점

“메일을 다시 읽기 전에,
지금 내가 해야 할 일과 그 이유를 알 수 있을까?”

관찰 범위: 개인의 실제 메일 업무. 조직 전체 사용자 조사나 생산성 효과 검증으로 확대 해석하지 않았습니다.

업무를 파악하는 순서를 바꿨습니다.

사람이 매번 하던 맥락 정리는 AI가 돕고, 사용자는 정리된 업무를 검토하고 처리하도록 흐름을 구성했습니다.

AI, 시스템, 사람의 역할을 나눴습니다.

자동화할 해석과 일관되게 지킬 규칙을 구분했습니다. 완료·제외·복구처럼 업무 책임과 연결되는 판단은 사용자가 결정하도록 두었습니다.

04 / DECISIONS

세 가지 선택에, 기획 의도를 담았습니다.

무엇을 문제로 봤고 어떤 기준을 정했는지, 구현된 동작과 함께 확인할 수 있습니다. 아래 항목을 선택해 각 사례를 살펴보세요.

DECISION 01 · INFORMATION ARCHITECTURE

요청·담당·기한을 하나의 업무로 연결했습니다.

구현됨
발견한 문제
요약을 읽어도 내 행동을 다시 판단해야 했고, 같은 일이 여러 화면에 나타날 때 처리 상태가 달라질 수 있었습니다.
내가 정한 기준
대화의 맥락에서 실행할 업무를 분리하고, 내 행동·담당·기한·상태를 함께 보여 주도록 구성했습니다.
예외까지 설계
오늘·프로젝트·일정에서 명확히 같은 업무만 연결합니다. 담당자·기한이 충돌하거나 후보가 여러 개면 자동으로 합치지 않습니다.
기획 역량정보 구조 설계 · 업무 단위 정의 · 상태 일관성 · 자동 병합의 경계 설정

공개 데모를 직접 연결해 업데이트된 화면을 보여 줍니다. 회사·사람·메일은 가상이며, 완료·제외·기한·색 기록은 방문자 브라우저에 저장됩니다. 메일함 접속과 AI 호출은 하지 않습니다. 별도 화면에서 보려면 데모 새 창으로 열기.

DECISION 02 · HUMAN CONTROL

제외한 판단은 유지하고, 새 요청은 알렸습니다.

구현됨
발견한 문제
‘내 일 아님’으로 처리한 대화를 반복 분석하면 사용자가 같은 판단을 다시 해야 합니다. 한편 새 메일의 직접 수신 대상이 될 수도 있습니다.
내가 정한 기준
같은 대화는 새 답장이 와도 분석 제외를 유지합니다. 이후 받은 메일의 To에 본인 주소가 포함되면 별도 알림을 보여 줍니다.
예외까지 설계
참조(CC), 보낸 메일, 제외 이전 메일은 알림 대상에서 뺍니다. 알림만으로 분석을 재개하지 않고, 사용자가 제외를 되돌려야 복구합니다.
기획 역량사용자 통제권 · 예외 시나리오 · 알림 조건 · 되돌릴 수 있는 업무 정책

구현 근거: nwmail/feedback.py, nwmail/extract.py, nwmail/dashboard.py · 검증 시나리오: test_exclusions.py

DECISION 03 · SUSTAINABLE OPERATION

변경 여부에 따라 다시 분석할 범위를 나눴습니다.

구현됨
발견한 문제
메일이 쌓일수록 같은 문맥을 반복해서 보내는 분량이 늘어납니다. 모든 대화를 같은 방식으로 재처리하면 운영 부담도 커집니다.
내가 정한 기준
변화가 없으면 기존 결과를 재사용하고, 새 메일은 이전 정리 결과와 함께 분석합니다. 누적·기간 조건에 따라 문맥을 다시 정리합니다.
운영까지 설계
호출별 사용량·처리 시간·실패를 기록합니다. 입력 분량 감소와 결과 품질을 함께 확인할 수 있도록 비교 기준을 둡니다.
기획 역량자동화 범위 설정 · 운영 효율 · 관측 지표 · 품질과 사용량의 균형

구현 근거: nwmail/extract.py의 갱신 정책 · 호출 기록: nwmail/usage.py

07 / NEXT ITERATION

다음 질문은, “요약만 보고 이해할 수 있을까?”

사용 중 발견한 불편을 다음 개선 가설로 연결했습니다. 상세 요약은 아직 구현 전이며, 아래 화면은 동작과 정보 구성을 설명하는 기획안입니다.

기획 중 · 미구현

선택한 대화만,
필요한 깊이로 자세히 정리합니다.

프로젝트 요약을 봐도 원문을 다시 읽어야 이해되는 경우가 있었습니다. 기본 화면은 핵심 행동을 유지하고, ‘메일 요약하기’를 누른 대화에 배경·요청·현재 상태·미결사항을 추가하는 방식을 계획했습니다.

분석 범위

통제 조건
상세 요약이 완료·제외 상태를 바꾸지 않도록 하고, 제외된 대화의 재분석은 명시적으로 복구한 뒤 허용.
